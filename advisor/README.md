# Advisor 使用说明

Advisor 是按需顾问 Skill：主代理负责执行、验证和交付；遇到复杂取舍、证据冲突或聚焦排查仍然卡住时，才考虑调用 Astra 提供独立建议。

## 第一次怎么用

安装后从下一轮对话开始，直接正常描述任务即可，**不需要每次输入 `/advisor` 或 `$advisor`**：

```text
请分析这个技术方案。
目标是：……
约束是：……
现有证据是：……
验收条件是：……
```

Skill 可以被自动选择，但不会因此强制创建顾问。简单任务由主代理直接完成；只有第二意见确有价值时才创建 Astra 顾问。

如果你明确希望本次使用 Advisor，可以输入 `/` 后选择 `advisor`，或直接输入：

```text
$advisor 请审查方案 A 和方案 B，必要时请 Astra 做独立复核。
```

两种显式调用方式效果相同。如果要求一定获取 Astra 的第二意见，请在任务中明确写出来。

顾问默认使用 Medium；复杂逻辑使用 High，特别困难的分析可选 XHigh 或 Max。Ultra 不作为普通顾问的自动升档。实际可用模型和档位以当前环境为准。

## 怎么看结果

最简单的方法是在 Codex 中直接说：

```text
汇总 advisor 最近的使用效果。
```

也可以说：

```text
汇总 advisor 最近 10 次的使用效果，列出是否调用顾问、建议采纳情况、验收结果、耗时、用户纠错、返工和能确认的 token 用量。
```

命令行基础汇总：

```bash
python3 "${CODEX_HOME:-$HOME/.codex}/skills/advisor/scripts/log_event.py" report --limit 10
```

实际执行流程会把基础指标与关联 ID 记录到 `${CODEX_HOME:-~/.codex}/advisor-metrics/events.jsonl`。这不是后台监控；强制中断可能留下未结束记录。用量和费用只在用户要求汇总时按需采集，缺失数据标记未知，API 价格折算不代表订阅实际扣费。

## 怎么与普通单代理对比

日常任务不会自动重跑。要做有效对比，请准备两个相同起点的独立任务或工作副本，使用相同需求、资料、主模型、推理强度和验收条件，并避免 Advisor 组读取 solo 组的答案。

第一组：

```text
这次是 advisor 对照任务，编号 import-01，模式 solo。
只由主代理完成，不调用任何子代理；记录基础指标和对照条件。
任务：……
起点与输入资料：……
验收条件：……
```

第二组在独立环境中运行：

```text
这次是 advisor 对照任务，编号 import-01，模式 advisor。
按需使用顾问；记录基础指标和对照条件。
任务：……
起点与输入资料：……
验收条件：……
不要读取 solo 组的结果。
```

两次完成后说：

```text
比较编号 import-01 的 solo 与 advisor 运行效果。
```

系统会先比较验收证据，再比较耗时、纠错、返工、顾问贡献和可确认的用量。缺一组会标记“缺少对照”；条件不一致时只并列展示；同一编号有多次运行时需要指定两个 `run_id`。完整任务用量无法可靠归属时，不计算节省比例。

两次执行会分别消耗额度，Skill 不会自动启动第二次。完整规则见 [comparison.md](references/comparison.md)，指标口径见 [metrics.md](references/metrics.md)。单次样本不代表所有任务都更快或更省。
