# Advisor 使用说明

Advisor 是按需顾问 Skill：主代理执行任务，复杂取舍、证据冲突或排查卡住时考虑调用 Astra 提供只读建议。支持自动触发，也可输入 `$advisor 帮我完成……`。简单任务不必创建顾问。

顾问默认 Medium；复杂逻辑用 High，特别困难的分析可选 XHigh 或 Max。Ultra 不作为普通顾问的自动升档。实际可用档位以当前环境为准。

## 使用记录

进入实际执行流程时记录基础指标与关联 ID，保存在 `${CODEX_HOME:-~/.codex}/advisor-metrics/events.jsonl`。用量、费用仅在你要求汇总时采集；不存在后台统计。缺失数据标记未知，API 价格折算不代表订阅实际扣费。

可以说：“汇总 advisor 最近的使用效果。”

## 可选的单代理对照

只有明确指定对照任务时才添加对照编号、组别和条件；日常任务不增加这些字段，也不会自动重跑。详细规则在 [comparison.md](references/comparison.md)。

选择两个相同起点的独立工作副本或任务，使用相同需求、资料和验收条件，避免后一组读取前一组的答案。主模型和推理强度也应一致。

第一组示例：

```text
这次是 advisor 对照任务，编号 import-01，模式 solo。
只由主代理完成，不调用任何子代理，但记录基础指标和对照条件。
任务：……
起点与输入资料：……
验收条件：……
```

第二组在独立环境中使用：

```text
这次是 advisor 对照任务，编号 import-01，模式 advisor。
按需使用顾问，记录基础指标和对照条件。
任务、起点、输入资料和验收条件与 solo 组一致：……
不要读取 solo 组的结果。
```

两次运行后说：

```text
比较编号 import-01 的 solo 与 advisor 运行效果。
```

这时才检查配对、验收、耗时、返工和可获取的用量。只有一组会显示“缺少对照”；条件无法核实则只并列展示。若同一编号有多次运行，需要明确选择哪两个 run_id。

对照不会自动创建第二次运行；第二次执行本身会额外消耗额度。增加少量记录也有开销，完整对照规则仅在指定或比较对照任务时读取。

完整任务用量或费用无法可靠归属时，不计算节省比例。单次结果只说明该样本，不代表所有任务都更快或更省。
