# Advisor

主代理负责沟通、实现、验证和交付；顾问提供判断依据。推荐在 Sol Medium 任务中使用，但保留用户选定的主模型，不自动切换模型或修改全局配置。若主代理已是 Astra，通常直接解决，只有独立第二意见确有价值时才请顾问。

## 何时协作

- 简单修改、已知操作和常规实现直接完成。
- 架构取舍影响较大、证据冲突，或经过聚焦排查仍无法定位时，才调用顾问；先用一句话说明需要它解决的具体问题。
- 本 Skill 明确请求在这些条件下使用 collaboration 子代理。不要为协作创建侧栏任务，也不要递归分派。

## 调用与职责

- 先确认当前工具提供所需模型和参数。使用 `spawn_agent`，指定 `model: "gpt-6-astra"`、`fork_turns: "none"`；一般独立复核用 `reasoning_effort: "medium"`，困难推理用 `"high"`。不要默认最高强度。
- 给顾问自包含的精简任务包：目标、验收条件、必要约束、相关路径及证据、已尝试方法、待回答问题，以及当前任务的必要权限边界。新上下文不继承完整对话，不得假定它知道此前决定。
- 明确要求顾问只读、不修改文件、不执行外部变更、不再创建子代理；返回结论、依据或文件位置、关键风险和最小必要验证建议，避免重述任务背景。
- 每个用户任务默认最多创建一个顾问。同一问题后续需要补充时，优先向已有顾问发送增量信息并复用它；避免反复讨论没有新证据的问题。
- 仅存在独立且有价值的只读定位任务时，可额外创建一个 `gpt-5.6-sol` 侦察员，使用 `reasoning_effort: "low"`、`fork_turns: "none"`，同样禁止继续分派。并发最多三个代理，包括主代理，并遵守环境更低的上限。用户可明确调整预算。
- 顾问运行时推进不依赖其结论的工作，避免重复调查。通过当前可用的消息和等待工具接收结果，结束前收齐必要结论。
- 模型或工具不可用时，说明具体限制并用当前主代理继续可完成的工作；不要静默替换指定模型或声称调用成功。

## 验证与开销

主代理根据证据判断顾问建议，执行必要修改和与风险相称的检查。检查通过后，仅在新变更、失败或未解决疑点出现时扩大或重复验证。不要为节省用量省略验收要求。

只传递相关上下文；不要把整个聊天或冗长日志复制给每个代理。精简上下文与混合模型不保证省钱，不声称共享跨模型缓存，不通过 Skill 设置 API 缓存或修改推理缓存配置。

交付时简要说明实际调用了哪个模型、解决了什么、采纳了什么以及验证结果；未调用则无需额外展开。没有实际用量证据时，不报告节省比例。

## 自动记录效果

每次显式调用本技能时，按 [效果记录规则](references/metrics.md) 自动记录本地开始和结束事件，包括未调用顾问的任务。记录仅由主代理写入，不额外创建统计子代理。它是任务执行中的记录步骤，不是后台监控；不要为采集指标扩大任务或扫描其他会话。
