# Advisor

主代理负责沟通、实现、验证和交付；顾问提供判断依据。推荐在 Sol Medium 任务中使用，但保留用户选定的主模型，不自动切换模型或修改全局配置。若主代理已是 Astra，通常直接解决，只有独立第二意见确有价值时才请顾问。

## 何时协作

- 简单修改、已知操作和常规实现直接完成。
- 满足下述难题条件时可自动使用本技能，无需用户输入 `$advisor`；用户明确要求单代理或不使用顾问时不触发顾问流程。指定单代理对照时仅使用下方记录规则，禁止调用任何子代理。仅发现或读取本技能不等于启动顾问流程。
- 架构取舍影响较大、证据冲突，或经过聚焦排查仍无法定位时，才调用顾问；先用一句话说明需要它解决的具体问题。
- 本 Skill 明确请求在这些条件下使用 collaboration 子代理。不要为协作创建侧栏任务，也不要递归分派。

## 调用与职责

- 先确认环境启用了 `[features] multi_agent = true`，且所需模型在可用覆盖列表中。用 `spawn_agent` 创建顾问：

  | 参数 | 值 | 说明 |
  |---|---|---|
  | `task_name` | 如 `advisor_review` | 仅小写字母、数字、下划线 |
  | `model` | `gpt-6-astra` | 见「模型配置」 |
  | `reasoning_effort` | 见「顾问推理强度」 | 默认 medium，按需升档 |
  | `fork_turns` | `"none"` | 不继承上下文，任务包必须自包含 |
  | `message` | 自包含任务包 | 见下条 |

  MultiAgentV2 只接受 `fork_turns`（`fork_context` 已废弃）。
- 给顾问自包含的精简任务包：目标、验收条件、必要约束、相关路径及证据、已尝试方法、待回答问题，以及当前任务的必要权限边界。新上下文不继承完整对话，不得假定它知道此前决定。
- **只读边界靠提示词，不靠平台。** `spawn_agent` 没有沙箱或只读参数，顾问默认继承主代理的全部工具（含写入）并且默认能继续分派。因此必须把这些约束写在任务包的**第一段**而非末尾附注：只读、不修改文件、不执行外部变更、不再创建子代理。要求返回结论、依据或文件位置、关键风险和最小必要验证建议，避免重述任务背景。
- 每个用户任务默认最多创建一个顾问。同一问题后续需要补充时，优先向已有顾问发送增量信息并复用它；避免反复讨论没有新证据的问题。
- 仅存在独立且有价值的只读定位任务时，可额外创建一个 `gpt-5.6-sol` 侦察员，使用 `reasoning_effort: "low"`、`fork_turns: "none"`，同样禁止继续分派。并发预算读环境配置（`max_concurrent_threads_per_session`），不硬编码数字；未知时按保守值处理并遵守环境上限。用户可明确调整预算。
- 顾问运行时推进不依赖其结论的工作，与顾问保持互不重叠的分工。`wait_agent` 仅在结论成为关键路径阻塞项时调用一次，而非反射式轮询；结束前收齐必要结论。
- **拿到结论后立即 `close_agent`。** 已完成的代理在关闭前仍占用并发额度。交付前确认本次创建的顾问和侦察员都已关闭。中途需要中止用 `interrupt_agent`，它仍可接收后续消息；确认不再需要时才 `close_agent`。
- 模型或工具不可用时，说明具体限制并用当前主代理继续可完成的工作；不要静默替换指定模型或声称调用成功。

## 模型配置

- 顾问：`gpt-6-astra`；侦察员：`gpt-5.6-sol`。变更模型只改本节。
- 模型覆盖列表由运行环境提供，可能为空或不含上述模型。此时说明具体限制，用当前主代理继续可完成的工作，不静默替换指定模型，也不声称调用成功。

## 顾问推理强度

- `medium`：一般独立复核的均衡默认值。
- `high`：需要追踪复杂逻辑、检验假设或分析边界情况。
- `xhigh` / `max`：特别困难、确需更深规划或分析的问题。官方没有给出两者的精确任务分界；本 Skill 的实践约定是，优先按所需深度选择 `xhigh`，最困难且深度比速度、用量更重要时选择 `max`。这些不是已验证的质量或成本保证。
- 可直接选择合适档位，不逐档试跑。若已有结论仍不足，先指出尚未解决的具体疑点及升档预期收益；缺证据先补证据，不因文件多、耗时长或一次检查失败自动升档。满足验收要求即停止。
- 当前跟进工具若不能修改已有顾问的推理强度，不假装已升档，也不为升档绕过默认一个顾问的预算。可继续向原顾问补充证据；确需替换顾问时，由用户明确调整创建预算后进行。
- `ultra` 不作为普通只读顾问的自动升档终点。产品 Ultra 包含主动并行委派；只有用户明确要求扩大协作范围时，才按当前环境支持情况及用户指定的分工、预算采用独立的编排安排。本 Skill 的叶子顾问仍不得继续分派，也不自动切换主模型或修改全局配置。
- 使用高于 `medium` 的强度时，简要说明选择理由，并在已有任务记录中如实记录实际强度；用户明确指定的可用档位和预算优先。

依据：[官方子智能体指导](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[模型与 Max/Ultra 模式](https://learn.chatgpt.com/docs/models)。API 与产品可用档位不同，以当前调用工具为准。

## 验证与开销

主代理根据证据判断顾问建议，执行必要修改和与风险相称的检查。检查通过后，仅在新变更、失败或未解决疑点出现时扩大或重复验证。不要为节省用量省略验收要求。

只传递相关上下文；不要把整个聊天或冗长日志复制给每个代理。精简上下文与混合模型不保证省钱，不声称共享跨模型缓存，不通过 Skill 设置 API 缓存或修改推理缓存配置。

交付时简要说明实际调用了哪个模型、解决了什么、采纳了什么以及验证结果；未调用则无需额外展开。没有实际用量证据时，不报告节省比例。

## 自动记录效果

显式调用本技能执行实际任务，或满足难题条件后自动进入顾问流程时，按 [效果记录规则](references/metrics.md) 记录本地开始和结束事件。记录包括进入流程后未成功调用顾问的情况；简单任务仅考虑后未触发本技能，以及技能解释、修改和汇总，不新增执行样本。写入统一用 `scripts/log_event.py`（`start` / `end`），它负责 UUID、UTC 时间戳、序列化、追加与写后校验；`ADVISOR_METRICS=0` 可关闭记录，脚本返回非零时任务继续并如实说明未记录。记录仅由主代理写入，不额外创建统计子代理。它是任务执行中的记录步骤，不是后台监控；不要为采集指标扩大任务或扫描其他会话。

日常任务只记录基础指标和关联 ID。只有用户主动要求汇总、查看用量或计算成本时，才采集日志用量并折算金额；每次任务结束或再次调用本技能都不自动统计。

## 可选对照

只有用户明确指定对照任务或要求配对比较时，才读取 [对照规则](references/comparison.md)。日常任务不添加对照字段、不自动配对或重跑。`solo` 对照只记录基础指标，不创建顾问或侦察员；两组均独立运行且条件可核实时，才按用户请求比较。使用方法见 [README](README.md)。
