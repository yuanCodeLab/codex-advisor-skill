# Advisor

主代理负责沟通、实现、验证和交付；顾问提供判断依据。推荐在 Sol Medium 任务中使用，但保留用户选定的主模型，不自动切换模型或修改全局配置。若主代理已是 Astra，通常直接解决，只有独立第二意见确有价值时才请顾问。

## 何时协作

- 简单修改、已知操作和常规实现直接完成。
- 架构取舍影响较大、证据冲突，或经过聚焦排查仍无法定位时，才调用顾问；先用一句话说明需要它解决的具体问题。
- 本 Skill 明确请求在这些条件下使用 collaboration 子代理。这是平台要求的显式授权：Codex 默认禁止分派，仅"要深入""要彻底调研"不构成授权。不要为协作创建侧栏任务。

## 调用与职责

- 先确认当前环境启用了 `[features] multi_agent = true`，并确认所需模型出现在可用覆盖列表中。
- 用 `spawn_agent` 创建顾问，参数：

  | 参数 | 值 | 说明 |
  |---|---|---|
  | `task_name` | 如 `advisor_review` | 仅小写字母、数字、下划线 |
  | `model` | `gpt-6-astra` | 见下方「模型配置」 |
  | `reasoning_effort` | 一般 `medium`，困难推理 `high` | 平台支持 low/medium/high/xhigh/max/ultra；默认 medium，按需升档 |
  | `fork_turns` | `"none"` | 不继承上下文，任务包必须自包含 |
  | `message` | 自包含任务包 | 见下条 |

  MultiAgentV2 只接受 `fork_turns`（`fork_context` 已废弃）。
- 给顾问自包含的精简任务包：目标、验收条件、必要约束、相关路径及证据、已尝试方法、待回答问题，以及当前任务的必要权限边界。新上下文不继承完整对话，不得假定它知道此前决定。
- **只读边界靠提示词，不靠平台。** `spawn_agent` 没有沙箱或只读参数，顾问默认继承主代理的全部工具（含写入）并且默认能继续分派。因此必须把这些约束写在任务包的**第一段**，而不是末尾附注：只读、不修改文件、不执行外部变更、不再创建子代理。返回结论、依据或文件位置、关键风险和最小必要验证建议，避免重述任务背景。
- 每个用户任务默认最多创建一个顾问。同一问题后续需要补充时，用 `send_message` 向已有顾问发增量信息并复用它，避免反复讨论没有新证据的问题。
- 仅存在独立且有价值的只读定位任务时，可额外创建一个 `gpt-5.6-sol` 侦察员，`reasoning_effort: "low"`、`fork_turns: "none"`，同样在任务包首段写明只读且不再分派。
- **并发预算读环境配置**（`max_concurrent_threads_per_session`），不要硬编码数字；未知时按保守值处理并遵守环境上限。用户可明确调整预算。

## 结果回收与释放

- 顾问运行时推进不依赖其结论的工作，与顾问保持互不重叠的分工。`wait_agent` 仅在结论成为关键路径阻塞项时调用一次，而非反射式轮询。
- **拿到结论后立即 `close_agent`。** 已完成的代理在关闭前仍占用并发额度。交付前确认本次创建的顾问和侦察员都已关闭。
- 顾问中途需要中止时用 `interrupt_agent`，它仍可接收后续消息；确认不再需要时才 `close_agent`。

## 模型配置

- 顾问：`gpt-6-astra`；侦察员：`gpt-5.6-sol`。变更模型只改本节。
- 模型覆盖列表由运行环境提供，可能为空或不含上述模型。此时说明具体限制，用当前主代理继续可完成的工作，不静默替换指定模型，也不声称调用成功。

## 验证与开销

主代理根据证据判断顾问建议，执行必要修改和与风险相称的检查。检查通过后，仅在新变更、失败或未解决疑点出现时扩大或重复验证。验收要求优先于用量节省。

只传递与问题相关的上下文片段，而非整个聊天或冗长日志。精简上下文与混合模型不保证省钱。

交付时简要说明实际调用了哪个模型、解决了什么、采纳了什么以及验证结果；未调用则无需额外展开。

## 诚实性底线

- 不声称共享跨模型缓存，不通过本 Skill 设置 API 缓存或修改推理缓存配置。
- 没有实际用量证据时，不报告 token、费用或节省比例。
- 记录写入失败时如实说明未记录，不能声称保存成功。

## 自动记录效果

每次显式调用本技能时，用 `scripts/log_event.py` 记录开始和结束事件，包括未调用顾问的任务：

```bash
RUN_ID=$(python3 scripts/log_event.py start --task-label <脱敏类别> \
  --main-model <当前模型或省略> --main-effort <当前强度或省略>)

python3 scripts/log_event.py end --run-id "$RUN_ID" --status completed \
  --acceptance passed --verification-summary "<实际检查结果>" \
  --agents-file <agents.json> --usage-file <usage.json>
```

脚本负责 UUID、UTC 时间戳、JSON 序列化、追加写入和写后校验；字段语义与填写口径见 [效果记录规则](references/metrics.md)。`ADVISOR_METRICS=0` 可关闭记录。脚本返回非零时任务继续，最终如实说明未记录及原因。

记录仅由主代理写入，不额外创建统计子代理。它是任务执行中的记录步骤，不是后台监控；不要为采集指标扩大任务或扫描其他会话。
