# 指定任务的配对对照

仅在用户明确要求时使用；不要自动重复执行任务、创建另一组任务或补造基线。不要求每个任务都有对照。

## 记录一次运行

1. 沿用 [基础指标规则](metrics.md) 的 start/end 事件、UUID run_id 和必要关联清单；即使模式为 solo 也记录。对照模式优先于自动顾问触发：solo 禁止所有子代理；advisor 按需使用顾问，不强制创建。
2. 在 start 事件增加 `comparison_id`、`mode`（solo 或 advisor）及 `comparison_conditions`。同一对照用同一 comparison_id，不同实际运行始终用不同 run_id。用户提供编号则沿用；没有则生成 UUID 并告诉用户，供另一组复用。未指定组别且无法确定时只询问组别，不先运行。
3. comparison_conditions 保存简短脱敏的任务规格、起点证据（例如提交 ID，加上工作树是否干净；有改动时须另有能识别初始快照的证据）、输入资料版本、验收条件、主模型及推理强度、环境差异、是否接触另一组结果。未知为 null，不用完整源码或提示词做日志。只有相同提交不足以证明脏工作树起点相同。
4. 从执行前开始计时，timing_scope 为 whole_task；迟到的指定不能补造之前计时。可以追加 `comparison_assignment` 事件，将已存在的 run_id 与上述字段关联，保留原始记录；必须有用户指定及已有起点证据，否则标明无法核实。不得按任务标题或时间接近自动配对。
5. 保留原始验收、返工、顾问和用量字段。普通交付只记录，不运行用量采集器或生成对照分析。记录失败如实说明。仅讨论对照功能不记为执行样本。

## 用户请求比较时

- 按 comparison_id 读取两个明确的 run_id；每个 run_id 的最新 comparison_assignment 可补充归属。若同一编号有多次 solo 或 advisor，不挑最好成绩；让用户指定配对，或分列所有运行且不计算单一节省比例。
- 缺少一组标记“缺少对照”；无结束事件标记“未结束”；起点、输入、验收或独立性无法核实，标记“不可直接对照”，可并列展示但不宣称改进由 Skill 导致。
- 主模型、强度或环境不同要显著披露，不能称为仅比较 Skill 的效果。advisor 组未实际调用子代理时，说明本次没有顾问介入，不能据此评价顾问贡献。
- 先比较验收及检查证据，再展示耗时、纠错、返工和完整度。用户满意与代理自报验收不同。只有两边 whole_task 计时、验收同等满足且条件可比，才报告耗时差；含等待，不称纯推理速度。
- 用量读取仍按 metrics.md 的显式统计流程；最新快照不累加。只有计数互斥已验证、轮次完整、whole_run 口径一致时，才计算任务总用量变化；否则分列已知数据与缺失，不推算总节省。
- 对可比且完整的指标，变化比例为 `(solo - advisor) / solo`，solo 为零时不计算。输入、输出分别比较；不把总 token 当真实费用。API 情景估算、实际费用、订阅额度不可混为一谈。现有采集器若尚不支持可靠任务总价，费用节省保持未知。
- 汇总在对话中输出；只有用户要求时才另存报告。单组对照仅是一个样本，不推广为所有任务的收益。
